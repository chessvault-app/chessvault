# 미리 준비하는 데이터베이스

*[English](databases.md) · 한국어*

앱의 기능 두 가지는 앱이 만들어 내는 것이 아니라 **한 번 만들어 서버로
복사하는** 데이터베이스를 읽습니다:

| 파일 | 무엇이 읽는가 | 크기 |
| --- | --- | --- |
| `data/puzzles.sqlite` | 퍼즐 트레이너 | 약 2.5 GB |
| `data/refgames.sqlite` | 게임 탭의 엘리트 게임 브라우저 | 색인한 한 달치당 약 160 MB |

그 밖의 모든 것 — 북, 스터디, 노트, 가져온 퍼즐 책 — 은 앱 안에서
만들어집니다. `data/mygames.sqlite`는 그조차 아닙니다. 탐색기의 내 게임
색인이 보관함의 PGN 파일에서 스스로 만들어지고 스스로 따라가므로, 사용자가
할 일이 아예 없습니다. 이 둘은 예외이고, 일부러 그렇게 두었습니다. 입력이 수백
메가바이트짜리 공개 덤프라 브라우저로 올리고 싶은 사람이 없고, 빌드는
사용자가 하는 일이라기보다 특정 시점을 고정하는 일회성 작업이기
때문입니다.

## 무언가를 해야 할 때

거의 없습니다. 배포가 색인과 카운트 테이블을 최신으로 유지하고
(`scripts/deploy.sh`가 `tune-dbs.ts`를 돌립니다), 파일 자체는 저절로
바뀌지 않습니다.

다시 만들 이유는 정확히 둘뿐입니다:

**더 새로운 퍼즐 모음.** Lichess가 주기적으로 갱신된 덤프를 냅니다.
받으려면:

```
# 1. 덤프 내려받기 (CC0, 약 304 MB, 약 310만 퍼즐)
curl -O https://database.lichess.org/lichess_db_puzzle.csv.zst
mv lichess_db_puzzle.csv.zst data/
# 2. 빌드 (임시 파일에 쓴 뒤 이름을 바꿉니다 — 돌아가는 서버는 끝날
#    때까지 기존 데이터베이스를 계속 서빙합니다)
npm run build:puzzles
# 3. 결과를 서버의 data 디렉터리로 복사하고 재시작
```

시도 기록은 보관함에 있고 퍼즐 id로 키를 잡으므로, 다시 만들어도
살아남습니다.

**참고 게임 늘리기.** `vault/sources/`에 PGN 파일을 넣고:

```
npm run build:refgames                    # vault/sources/의 모든 PGN
npm run build:refgames -- elite-2025-11.pgn
```

## 왜 앱 안에서 만들지 않는가

모든 사용자 동작은 앱 안에서 가능해야 한다는 것이 계속 지키는
규칙인데, 여기가 그것이 지켜지지 않는 유일한 곳입니다. 실수가 아니라
따져 본 예외입니다. 입력이 수백 메가바이트 단위의 공개 아카이브이고,
빌드는 몇 분 동안 CPU를 붙들며, 결과는 누군가의 개인 데이터가 아니라
그 배포를 쓰는 모두가 공유하는 스냅숏입니다. 엔진 바이너리를 설치하는
일처럼, 서버를 세우는 과정의 일부로 여기세요.

언젠가 그 전제가 무너진다면 — 덤프가 충분히 작아지거나, 서버 쪽 작업으로
노출할 만해진다면 — 정직한 해법은 누군가가 알고 있어야 하는 스크립트가
아니라 앱 안의 빌드 작업입니다.
