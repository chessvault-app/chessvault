# 책 가져오기 파이프라인

*[English](book-import-pipeline.md) · 한국어*

스캔한 전술책 PDF를 보관함의 퍼즐 책으로 바꿉니다. 국면, 검증된 정답,
퍼즐마다의 근거 이미지, 그리고 정직한 신뢰 등급이 결과물입니다. 모든
것이 로컬에서 돌아가고, 중요한 것은 만들어진 보관함 파일뿐입니다.

## 들어오는 길은 둘, 코드는 하나

**앱 안에서**가 보통의 방법입니다. 퍼즐 책을 열고 PDF를 가져오면
브라우저가 전부 처리합니다 — 페이지를 렌더링하고, 다이어그램을 찾고,
CellNet으로 읽고, 페이지의 텍스트 레이어를 읽고, 번호를 다이어그램에
짝지어 주고, 이 책이 정답을 어떻게 적는지 알아내고, 재생되는 것을
번호가 붙은 퍼즐로 근거와 함께 저장합니다. 사용자는 파일 하나를 고를
뿐이고, 설정할 것도 없으며, 그 책에 대해 어디에도 적어 두는 것이
없습니다.

**오프라인**은 예비 경로이자 실험실입니다. 아래 단계들은 미리 렌더링해
둔 페이지에 대해 같은 공유 코드(`shared/bookImport.ts`,
`shared/bookConfigSearch.ts`, `shared/bookSolve.ts`)를 돌리며, 덕분에
브라우저에서 다시 스캔하는 대신 1분 안에 책 한 권 전체에 대해 변경을
측정할 수 있습니다. 또한 앱이 아직 갖지 못한 두 가지 패스 — 글리프
힌트와 정답으로 제약한 보드 복구 — 를 여전히 지니고 있는데, 그것이
1001 Chess Exercises에서 667과 707의 차이입니다.

`scripts/ml/books/` 아래의 책별 설정 파일은 오직 오프라인 쪽의
것입니다. 앱은 그중 아무것도 명시하지 않습니다. 번호 방식과 상한은 책
자신의 번호 매김에서 읽어 내고, 라벨 창은 책의 배치에서 맞춰 내고,
표기법은 탐색하며, 정답 페이지는 이긴 앵커가 걸리는 곳입니다.

## 핵심 발상: 책이 스스로를 증명한다

퍼즐이 **book solution**으로 들어오는 것은 사슬 전체가 합의할 때뿐입니다.
다이어그램이 국면으로 읽혔고, 인쇄된 정답이 수로 해석되었으며, 그 수들을
그 국면에서 재생하는 것이 합법적일 때(주장된 메이트가 실제로 메이트여야
하고, 국면이 기물 수 도달 가능성 관문을 통과해야 합니다). 한 번의
성공이 세 입력을 한꺼번에 검증합니다. 사슬을 통과하지 못한 것은 엔진이
뒷받침하는 등급이나 초안으로 부드럽게 내려앉습니다 — 조용히 버려지는
것은 없습니다.

## 단계 (`scripts/ml/`)

1. **텍스트 레이어 덤프** — `extract_pdf_words.py <book.pdf> <out.json>`:
   pymupdf 단어 상자 + 페이지 텍스트.
2. **측정** — `autoimport-measure.ts <pages_dir> --book <cfg>`:
   페이지마다 다이어그램을 찾고, 각각을 인쇄된 번호에 맞추고, CellNet으로
   64칸을 읽고, 정답 챕터를 해석하고, 재생합니다. 패스는 이렇습니다:
   - 1패스: 그냥 재생;
   - 2패스: 학습한 **피겨린 방언**(엉망인 OCR 접두사 → 기물, 이 책
     자신의 검증된 항목에서 배웁니다);
   - 3패스: `--glyph-hints`(이미지에서 읽은 피겨린 글리프, 아래 참고);
   - 4패스: `--repair` — 정답으로 제약한 보드 복구: 분류기의 차점
     라벨로 변화를 다시 시도합니다(어디든 1칸, 가장 자신 없는 것들
     가운데 2칸, 테스트 시점 증강 투표를 우선). 유일하게 동작하는
     국면만 받아들이고, 동점은 `repairCandidates`로 내보냅니다.
   `--jobs N`은 페이지 판독과 복구 탐색을 N개의 자식 프로세스로
   나눕니다. 판독 결과는 `<slug>-reads.json`에 캐시되고(사각형과 쪽
   정보 포함), `--emit <dir>`은 근거 이미지를 위해 보드/페이지 회색
   이미지를 내놓습니다.
2b. **거꾸로 된 페이지** — `derotate.ts <pages_dir> --book <cfg>`:
   다이어그램은 있는데 번호도 평범한 영어도 없는 페이지를 찾아 렌더를
   되돌려 놓고, 그 페이지가 남긴 번호의 빈틈에서 번호를 되찾습니다 —
   빈틈의 너비가 그 구간의 다이어그램 개수와 정확히 같을 때만 그렇게
   합니다. 두 번째 측정 패스를 위한 `--extra-labels` 파일을 냅니다.
3. **가져오기** — `autoimport-import.ts <emit_dir> --book <cfg> --jobs N`:
   모든 항목에 등급을 매깁니다. 검증됨 → book-parsed. 아니면 Stockfish가
   읽어 낸 국면을 풉니다 — 결정적이면서 책의 항목이 언급한 칸과 겹치면
   engine-corroborated, 결정적이기만 하면 engine-only, 합법적이고 쪽을
   알면 engine-unverified, 나머지는 초안입니다. 복구의 동점도 여기서
   결판납니다. 엔진 변화가 결정적이고 칸으로 뒷받침되는 후보가 정확히
   하나면 book solution으로 들어옵니다. 엔진 결과는
   `<report>-engine-cache.json`에 캐시되어 다시 가져오기가 쌉니다.
   보관함의 책(puzzles/drafts/book.json + 근거 목록)을 씁니다.
4. **근거 이미지** — `evidence_jpegs.py`가 내놓은 회색 이미지를
   변환합니다.
5. **정답 페이지** — `enrich_solution_pages.py --book <cfg>`가 모든
   퍼즐과 초안에 그 번호를 담고 있는 정답 챕터 페이지를 새겨 넣어
   (`diagrams/`에 따로 렌더링됩니다) 트레이너에서 인쇄된 답을 들춰 볼 수
   있게 합니다.

자기 지도 방식의 텍스트 도우미 두 가지(둘 다 `--book`을 받습니다):
- `digit_labels.py` — 이미 맞춰진 번호들의 텍스트 레이어 단어 상자에서
  이 책의 숫자 모양을 배우고, 텍스트 레이어가 놓친 다이어그램 위의
  인쇄된 번호를 읽습니다(`--extra-labels`가 되찾은 것을 측정 단계로
  돌려보냅니다).
- `figurine_glyphs.py` — 검증된 항목의 인쇄된 토큰을 이미 아는 SAN과
  정렬해 피겨린 글리프 조각에 라벨을 붙이고, 엉망인 접두사를 모두 읽어
  3패스를 위한 접두사→기물 힌트를 냅니다.

## 책별 설정 (`scripts/ml/books/*.json`)

책마다 다른 사실은 전부 데이터입니다. 페이지 범위, 산출물 경로, 번호
방식(맨숫자 대 `123)`), 정답 앵커(`N - 1.` / `N) Name` / `N. Name`), 수
표시(점 있음 대 점 없음), 둘 차례가 어디에 인쇄되는지(`chapter` 머리글,
퍼즐마다의 `label` "White to play", 또는 번호 아래의 맨글자 W/B),
라벨을 맞추는 창, 그리고 테두리 바깥 여백에 좌표를 인쇄하는 책을 위한
`cropTrim`이 그렇습니다. 1001 책의 설정이 원래의 기본값을 담고 있습니다.

뒤에 정답 절을 한 번 두는 대신 **챕터마다** 두는 책은 그 구간들을
`solutionRanges`(`[[28,33],[45,48],…]`)에 적습니다. 이것이
"`solutionsAfterPage` 이후는 전부"라는 규칙을 대신하는데, 그 규칙은 절
사이에 끼어 있는 퍼즐 페이지까지 삼켜 버리기 때문입니다.
`render_book_pages.py`가 원본을 찾을 수 있도록 `pdf`(파일의 경로가 아니라
**이름** — 사본이 있는 폴더는 `CHESS_BOOK_PDFS`로 가리킵니다)와
`coverPage`를 추가하세요. 설정은 커밋합니다. 누군가의 디스크 배치는
커밋하지 않습니다.

## 실행 안내서 (책 한 권 기준)

```
# 한 번만: 텍스트 추출, 설정 작성, 페이지 렌더링
python extract_pdf_words.py book.pdf data/ml/<slug>-text.json
python harvest_pdfs.py book.pdf data/ml/<slug>-pages          # page-NNN.gray
npx tsx autoimport-measure.ts <renders> --book cfg.json --emit <emit> --repair --jobs 6
npx tsx derotate.ts <renders> --book cfg.json                 # 거꾸로 된 페이지가 있다면
npx tsx autoimport-measure.ts <renders> --book cfg.json --emit <emit> --repair --jobs 6   --extra-labels data/ml/<slug>-extra-labels.json
npx tsx autoimport-import.ts  <emit>    --book cfg.json --jobs 6
python evidence_jpegs.py
python render_book_pages.py cfg.json                          # 표지 + 정답
python enrich_solution_pages.py cfg.json
```

주의할 점: 다시 가져오면 `diagrams/`가 지워지므로, `evidence_jpegs.py`
뒤에 표지와 정답 페이지 jpg를 되살려야 합니다. `render_book_pages.py`가
바로 그 일을 합니다. 퍼즐 id가 `n<번호>`라서 진행 상황은 살아남습니다.
보드를 다시 읽으려면(예: 모델을 갱신한 뒤) 먼저
`<slug>-reads.json`을 지우세요. 그러지 않으면 판독은 캐시에서 오고 검증만
다시 돌아갑니다.

## 스캔을 건너뛰는 두 가지 가져오기

둘 다 책 전용 스크립트가 아닙니다. 여기의 다른 모든 것과 마찬가지로 책
자신의 사실은 `scripts/ml/books/*.json`에 있고, 코드는 자기가 어떤 책을
읽고 있는지 결코 알지 못합니다.

### `import-diagram-text.ts` — 이미 글자인 다이어그램

    npx tsx scripts/ml/import-diagram-text.ts --book scripts/ml/books/<slug>.json

다이어그램 글꼴로 LaTeX 조판된 책을 위한 것입니다. 모든 국면이 이미 칸마다
한 글자로 텍스트에 들어 있고(기물마다 밝은 칸용과 어두운 칸용 두 개의
글리프), 모든 정답이 평범한 대수 표기입니다. 인식하는 것이 아니라
읽습니다. 그래도 모든 항목은 가져오기 전에 chessops로 재생됩니다. 잘못
읽은 항목을 잡아내는 것이 그것이고, 정답이 기보 전체인 600개의 미니어처
게임 안에서 인쇄된 국면의 위치를 찾아내는 것도 그것입니다.

이 방식은 초안을 쓰지 않습니다. 초안은 가져오기가 읽지 못한 보드를
사람이 다시 읽으라고 있는 것인데, 여기서는 보드가 정확하고 해석에
실패하는 것은 남은 **정답**들이기 때문입니다. 그 번호들은 이유와 함께
실행 결과에 출력되고, id가 `n<번호>`라서 더 나은 파서가 그 자리에서
집어 올립니다.

여기서 얻은 교훈은 일반화됩니다. **CellNet에 손을 뻗기 전에 텍스트
레이어에 다이어그램 글리프가 있는지 확인하라.** `pdftotext` 한 번이면
되고, 모델 작업 일주일을 오후 한나절로 바꿀 수 있습니다.

### `import-annotated-games.ts` — 주석 달린 기보집을 스터디로

    python scripts/ml/extract_pdf_lines.py "<book>.pdf" data/ml/<slug>-lines.json
    npx tsx scripts/ml/import-annotated-games.ts --book scripts/ml/books/<slug>.json

게임 하나당 스터디 챕터 하나를 쓰고, 각 수는 그 수에 달린 책의 설명을
지닙니다. 수와 해설은 글꼴이 아니라 배치로 구분하며, 어떤 토큰도 그냥
읽지 않습니다. 모든 합법적인 수를 스캔의 잔해에 대해 점수 매기고, 인쇄된
모든 수가 여전히 해석되는 읽기를 찾아 게임 전체를 깊이 우선으로
탐색합니다. 끝까지 재생되지 않는 게임은 기록될 뿐 쓰이지 않습니다.

그 스캔 고유의 혼동 — 어떤 글자를 어떤 랭크에 쓰는지, 어떤 파일을 섞어
버리는지, 어떤 칸들을 하나의 글리프로 뭉개는지 — 는 책의 설정에
있습니다. 그것은 그 스캔의 것이지 다른 어떤 것의 것도 아니기
때문입니다.

(가장 최근 회차: 미세 조정한 CellNet과 3칸 복구 탐색으로 다시
측정했습니다. 퍼즐 id가 `n<번호>`라서 다시 가져와도 진행 상황이
살아남고, 따라서 파이프라인이 좋아지는 대로 보관함을 제자리에서 갱신할
수 있습니다.)

기록해 두는 계획: 초기 구축이 끝나면 모든 책을 그때의 모델과
파이프라인으로 처음부터 다시 가져옵니다.
