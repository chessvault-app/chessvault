Getting started

There are two ways to run Chess Vault, and both are the same app. The only difference is where the vault lives — the folder holding your games, studies, notes and puzzles.

  • On this machine. Download the installer for Windows, macOS or Linux from Releases and run it. No Node, no terminal; updates arrive through the app itself.
  • On a server. One small Linux box owns the vault, and every device — phone, laptop, desktop — becomes a client of it. The README has the server setup.

When in doubt, start with the first. The vault is a folder, so moving to a server later is copying a folder.

First run

The desktop app's first question is where your vault lives. Choose On this computer and everything stays on this machine; it then asks which folder:

  • App-managed vault — the app picks a folder in your user profile and gets on with it. You can move it later.
  • Open a folder… — any folder becomes your vault, including one you already have. Derived data (reference databases, indexes) lives inside it too, so moving or syncing the folder takes everything with it.

The other answer — On my server — makes the same app a window onto a server you host; the address must start with https://. The choice can be changed later, in Settings → Desktop app.

The first minutes

A fresh vault opens onto a Home page with a Set up your vault card suggesting three things, all done inside the app:

  1. Add your chess.com / Lichess usernames in Settings — the Games page fills itself from them.
  2. Open Puzzles and accept the puzzle database it offers to fetch. It takes a few minutes, keeps running if you leave the page, and the trainer works offline from then on.
  3. Import a scanned tactics book you own — see Puzzle books. This one can wait.

A Lichess token is only needed for the online extras — the online opening explorer, importing Lichess studies and puzzle history; see Settings. Everything else runs without one.

The vault

The vault is a folder of plain files: studies and games are PGN, notes are markdown, progress is JSON. Any editor opens them, Obsidian reads them as they are, and if this app ever goes away your chess opens in something else.

  • Backing up is copying the folder. Copy the vault folder and everything — derived databases and indexes included — goes with it.
  • Every document keeps its earlier versions. The clock button in a study's, game's or note's header opens the Earlier versions panel: pick a time to look at it, and restore it. The version you have now is kept too, so you can come back.
  • Deleted documents come back. Settings → Deleted documents restores studies, notes and games that are gone entirely.
  • Starting over. The Danger zone in Settings wipes the whole vault — it makes you type a confirmation phrase, and there is no undo.

The derived things — the puzzle pool, reference game databases, indexes — can always be deleted and rebuilt. No database holds your work hostage.

Finding your way

On a wide screen the left sidebar lists the pages: Games, Studies, Notes, Books, Puzzles, Opening map, then under Tools the Board, Editor, Explorer and Repertoire, and finally Databases. Below the sidebar sit the connection label, the Settings gear and the light/dark toggle. On a phone a bottom bar carries Home, Games, Studies, Notes, Puzzles and More — everything else lives under More.

Home

Home leads with what you were last doing: the Continue card resumes your latest study, last game and training in one tap. On a desktop it opens onto panels for training, recent games, puzzle books and recent work. Customise home (the sliders button) picks which destinations get a tile and in what order — the arrangement is stored in the vault, so every device agrees.

Saving

Documents save when you save them (Ctrl/⌘ S or the save control). Unsaved changes show a badge, and leaving a document asks first. If you would rather changes were written as you make them, turn on Auto-save in Settings → Documents — it is off by default.

The board

The Board (under Tools) is a free analysis board. Play moves and a full move tree grows, with variations, comments, annotation glyphs (!, ?! and the rest) and drawn arrows. The panel beside the board tabs between Moves, Engine and Explorer.

  • Loading a position. Load a position in the Moves menu takes a FEN, a PGN, or a picture — paste a screenshot or scan, drag four handles onto the diagram's corners, and the position lands on the board. Copy FEN and Copy PGN go the other way.
  • The engine. Stockfish 18 runs in the browser itself — no server, no internet needed. Switch it on in the Engine tab; its settings control lines (MultiPV), threads, hash, depth and a time limit.
  • Game review. Engine review judges every move (?! ? ??), measures accuracy and draws an evaluation graph you can click to jump. Known opening theory is marked as book moves and left unjudged.
  • Keeping a game. A loaded game joins your collection on the Games page with one button.

Explorer and editor

Explorer

The Explorer shows what has been played from the current position — a move table with game counts and win/draw/loss, plus top and recent games you can open. It reads from three kinds of source:

  • The Lichess database (online; needs the Lichess token from Settings) — filtered by level and time control.
  • Reference databases — the ones you build on the Databases page. These work offline.
  • My games — every game in the vault, answering what have I played here, and how did it go — filtered by which side you had, the outcome, the speed and the date; a listed game opens on the board.

Where the move table runs out, Search every game for this position takes over — a scan of the whole database for this exact position.

Editor

The Editor sets up any position: drag pieces from the palette, erase with the erase mode, set the side to move, castling rights and en passant. A legality indicator keeps watch, and Analyse this position hands the finished position to the board. It loads from FEN, PGN or a picture here too.

Studies

A study is a PGN document in chapters — an opening file, a collection of exercises, a set of ideas. Create one fresh, import a PGN (a Lichess study export arrives with all its chapters, comments and arrows), or pull studies straight from a Lichess account.

  • Chapters. Add chapters and sub-chapters, rename them, fold them away. A study grows big enough to hold a whole repertoire.
  • Reading and annotating. The pieces move whether you are reading or annotating; the annotating toggle shows and hides the editing tools — NAGs, per-move comments, drawn arrows — so the board stays uncluttered when you are just stepping through.
  • The panes beside the board are the Board's own: Moves, Engine, Chapters, Explorer. Engine review works here too.
  • Saving is lossless. A save is a round-trip that gives back exactly what was written, and a copy is parked in the vault so a browser that dies does not take the work with it.

Notes

Notes are markdown — headings, lists, quotes, code — and two things make them chess notes:

  • Live boards in the text. A ```chess fence embeds an interactive board between paragraphs; the editor's Insert a board button drops one in.
  • [[Wiki-links]]. The same syntax Obsidian uses, resolved across notes, studies and games, with autocomplete as you type. A note links a study, the study links a game, the game links back to the note where you worked out what went wrong — the material becomes one connected body of work.

The files stay readable in Obsidian: same markdown, same links.

Games

The Games page brings three things together: your collection, your online archives, and searching the reference databases.

The collection

A shelf for the games worth keeping. Import by pasting a PGN (bare moves work too — 1. e4 e5 2. Nf3 …), rename, bookmark, search. A collected game is annotatable exactly like a study: variations, comments, glyphs, arrows.

The archives

The chess.com and Lichess tabs browse your played games month by month (usernames come pre-filled from Settings). Filter by side and result, then add games to the collection one at a time or all at once with Select all new. Browsed months are cached on disk, so they reopen instantly and work offline.

Searching the databases

The Databases tab searches a reference database the way a desktop chess database would:

  • By text — players, opening names or ECO codes, A vs B. Filters narrow by opponent, tournament, date range, strength band, side and result.
  • By position — paste a FEN or set it up on a board, and relax the match by degrees: exact position → same pawns → same pawn files → same material. You can also ask that the position holds for a number of moves.
  • By material — presets from pawn endings to “a queen up”, or your own per-piece specification.

A found game opens on the board, and joins the collection with one button.

Databases

Reference databases are built from PGNs you upload. On the Databases page:

  1. Upload PGN collections — drop .pgn files in. Big tournament dumps or files of your own, either way.
  2. Tick and build — tick collections and press Build; they index into one searchable database of whole games. Building keeps going if you leave the page.
  3. Grow it — add collections to an existing database and only the games it does not already hold are indexed.

A built database becomes an explorer source, a search target on the Games page, a field for the repertoire trainer and a yardstick for the opening map. Each row has a Fast search toggle that holds the scan index in server memory — position and material hunts get many times faster — and an Optimize action that removes duplicates and compacts the file. Deleting a database keeps the PGN collections it was built from.

A desktop install ships with a starter database (one month of elite games, 38,977 of them) so the explorer answers from day one; a server install or source checkout starts empty.

Books

Books is a library of your chess books: upload any PDF and read it in the app, in a pane beside the analysis board. The file stays in your vault, and your page is remembered per book.

  • The diagram buttons. Every printed diagram gets a board button that sets that position up on the board beside it — the engine and explorer, straight from the book's own positions.
  • Reader tools. Page navigation, zoom, fit to width or page, rotation, and full-text search across the book.
  • The shelf. Sort by title, added, last read or size; group into collections; rename; and replace a book's PDF when a better scan turns up — your page is kept.

A tactics book can go one step further: import it as a puzzle book and its diagrams become solvable puzzles.

Puzzles

The trainer runs on the Lichess puzzle database (CC0). The first visit offers to download and build it — a few minutes, and it keeps running if you leave the page — and from then on it is fully offline: over six million puzzles living on this machine.

  • Solving. Find the winning move. A wrong move rolls the board back; Hint comes in two presses — first the piece, then the move (not counted as a fail); Solution counts as one. Solving reveals the themes and a link to the source game.
  • Difficulty and themes. Puzzle settings pick a difficulty band and a theme; the Themes page trains any theme directly.
  • The review ladder. What you miss comes back after a day, then 3, 7 and 21 — and retires after a clean solve at every step. Reviews are not counted against you.
  • The dashboard. Attempts, solves, solve rate, a breakdown by difficulty, book progress, and a history of every attempt — any puzzle can be replayed.

Puzzle books

Hand the app a scanned PDF of a tactics book you own, and an ML pipeline — running entirely in the app — reads the diagrams, parses the printed solutions, verifies them by replaying every move, and imports each puzzle with an honest fidelity tier. Nothing leaves this machine.

  1. Puzzles → Puzzle books → create a book and Import PDF. Progress shows page by page, pausing loses nothing, and you can use the rest of the app while it reads.
  2. A review step shows every diagram it found; untick the false positives and keep the rest.
  3. Where the solution parsed and replays legally, it becomes a full puzzle; where it did not, it stays a draft with its evidence attached — the original page scan, one click away — so you can finish it by hand against the scan. Nothing is imported on a guess.

A book trains two ways. Review rides the same spaced ladder as the main trainer; cycles are Woodpecker-style — the whole book in passes, every puzzle once per pass, scored by first attempts. The book trainer lets you explore freely and then Submit, judging your mainline against the book's printed answer — and saying so when you left the book's line but the engine approves. You can also add puzzles by hand (diagram → board → solution, with a Stockfish check) or correct one against the book's own scan.

Import only a book you own. The puzzles a book yields stay in your vault — which is also why no book comes bundled with the app.

Repertoire trainer

The trainer plays an opening against the field — the statistics of real games. Replies are drawn weighted-random from what was actually played in each position, so you meet the common moves often. It has two modes:

  • Free play — pick a side and an opening (searchable by name or ECO code, about 3,800 of them) and play against the field: the Lichess database (pick a strength band; needs the token) or any local reference database, the bundled one included, so it works offline. When the line leaves book, the engine takes over seamlessly.
  • Drill a study — recite one chapter (or the whole) of your own study against that same field. A move your study does not play is refused, and a session ends at the end of your prepared line, at a gap your study has no reply for, or where the database runs out.

What you fumble is remembered as a review pool — Drill a missed position — and gaps are reported beside it; a gap is fixed by editing the study, not by drilling. After a session you get an engine verdict, and can analyse the line or save it to a study.

The opening map

The opening map shows your preparation as a shape rather than a list. One map per colour — White and Black — holding the moves that define your repertoire, drawn as a constellation or a tree. Moves are added three ways: pick from what the field plays here, type a move, or Grow from my games — charting what your own games already play.

Point it at a field — your own games, the Lichess database, a local reference database — and each dot sizes by how often that move is actually played, the replies you have no answer for get badges, and a statistics panel counts what share of the field runs into your preparation.

Select a dot and the opening catalogue names it, while its panel shows what covers it: the linked studies and notes, the preparation depth — derived live from the linked studies, so it is always the truth rather than a stored claim — and what you have fumbled in drills. From there you can analyse, drill, or start a new study from the line. Only studies are allowed to say what is prepared; notes come along for the reader.

Settings

Everything you do as a user happens in the app — nothing needs a shell. What Settings holds:

  • Profile — display name and your chess.com/Lichess usernames; the usernames pre-fill the archive browser on the Games page.
  • Appearance — app language (English and Korean), theme (follow system/light/dark), density, colour schemes (a high-contrast one included), board theme, piece set, how to castle, board coordinates. These are per-device.
  • Sound — move and capture sounds, volume, and vibration where the device supports it.
  • Documents — the auto-save switch.
  • Security — an app password (which turns the lock screen on), authenticator-app 2FA (set up with a QR code), and signing this device out. A password matters when a server is reachable by others — a purely local install never sees the lock screen.
  • Lichess token — powers the online opening explorer, the repertoire trainer's Lichess source, and Lichess study and puzzle-history import. Create one on lichess.org with no scopes and paste it in; it is stored in the vault and never shown again.
  • Browsed games / Storage used — an inventory of cached archive months with a clear-all, and a breakdown of storage by area.
  • Deleted documents / Danger zone / Version — restoring deleted documents, wiping the vault, and the version, update check and licences.

On a phone

There is nothing to install: open your server's address in the phone's browser and add it to the home screen — a full app (a PWA) with an icon, splash screens and an offline shell. This is the second way of running it from Getting started: the vault lives on a server.

The app rearranges itself for a phone. The bottom bar carries the main pages, and on a page with a board it becomes that page's controls — move navigation, puzzle actions — the way the chess.com and Lichess apps do it.

Common questions

What is different in the demo?

The demo is the real app running on a sample vault inside your browser tab. Edit anything — a reload puts it back. What needs a server of your own is absent: profile, password and 2FA, the Lichess token (and so the online explorer), document history, database management. Install or host the app and those places become real.

The app will not open on macOS

The macOS build is unsigned. The first launch needs right-click → Open; after that it opens normally.

What works offline?

On a local install: essentially everything. The engine, fonts and icons ship with the app, and there are no runtime CDN calls. What needs the internet is the online database (Lichess), fetching new archive months, and importing from Lichess — archive months you have already browsed open from the cache.

Where is my data?

All of it in the vault folder, as plain files. The bottom of the Settings page names the exact path. Backing up is copying that folder.

Where to ask more

Bugs and questions go to GitHub issues. For how things work under the hood, the repository's docs folder has detailed write-ups of the repertoire trainer, the opening map, the databases and book import.
